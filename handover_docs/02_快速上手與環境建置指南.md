# 文檔二：快速上手與環境建置指南

> **目的**：讓新進工程師在 10~15 分鐘內成功運行本地預覽、執行全量回歸測試，並掌握後端 GAS 部署與前端雙軌 Git 發布的標準 SOP。

---

## 1. 前置條件與工具鏈
- **Node.js**：版本需 $\ge$ 18.0（Antigravity Agent 環境內建 `agy-node`，標準終端可直接使用 `node`）。
- **Python 3.x**：用於本機前端靜態預覽。
- **Git CLI**：注意版本控制專屬前端目錄 `src/frontend/`。
- **Google 帳號**：需具備三大物理試算表（Core, Chat, Progression）之編輯者權限。

---

## 2. 本地開發、驗證與預覽

### 2.1 執行全量自動化回歸測試
在專案根目錄下執行原生測試套件（全案測試套件 21 suites，589 tests，需 100% PASS）：
```bash
# Antigravity 終端（推薦）：
agy-node tests/run-all.js

# 標準本機終端 (Node 18+)：
node tests/run-all.js
```

#### 2.1.1 核心專項測試執行（個人獎勵與小組篇章連動機制）
針對後端重構後的「個人獎勵計入當年度結算分 (`settledTotalScore`) 與小組篇章即時連動」核心機制，日常開發或局部驗證時可單獨執行以下關鍵專項測試套件：
```bash
# 1. 全鏈路端到端回歸測試（涵蓋在籍獲獎、管理員發放個人/小組獎勵、入組截斷防禦、退組沉澱守恆、同晚小組跨篇章連動等六大情境）：
agy-node --test tests/unit/personalRewardGroupContribution.test.js

# 2. 夜間排程同晚小組連動測試（驗證組員獲獎即時累加 groupScoreMap，同晚小組篇章評估直接突破門檻解鎖篇章）：
agy-node --test tests/unit/personalRewardSameNightSync.test.js

# 3. 進度帳本持久化層測試（驗證 PLAYER 獎勵入帳 Col 5、GROUP 獎勵入帳 Col 2，且嚴格隔離保護 Col 6 joinBaseScore）：
agy-node --test tests/unit/personalRewardLedgerPersistence.test.js
```

#### 2.1.2 前端首頁點數面板改版專項測試
針對首頁右上角點數面板（`.hero-score-grid`）改版（上半小組總點數、下半個人點數、點擊統一開啟同行貢獻面板），可單獨執行專項測試：
```bash
agy-node --test tests/unit/homeScorePanelRefactor.test.js
```

### 2.2 啟動前端本地開發預覽
```bash
python scripts/serve_frontend.py
```
預覽伺服器監聽 Port 8000，瀏覽器造訪：`http://localhost:8000/html/index.html`。

> ⚠️ **本地預覽資料隔離警告（必讀）**：
> 前端 `src/frontend/html/runtime-settings.js` 預設直接配置**線上生產環境的三大 GAS Web App URL**。
> 當你在本地預覽頁面上進行註冊、修改資料、操練打卡或發送留言時，**請求會直接寫入線上真實生產試算表**！
> **安全測試指引**：
> 1. 本地預覽測試請一律使用專屬測試帳號（如 `TEST_USER`），嚴禁使用真實信徒帳號測試；
> 2. 若需進行破壞性測試，請在 `runtime-settings.js` 中將 Web App URL 切換為開發用測試 GAS 專案。

## 3. 後端生產環境部署流程（手動貼至 GAS）
三大微服務為試算表容器綁定專案 (Container-bound Scripts)，目前採手動同步部署至 Google Apps Script 網頁編輯器。

### 3.1 檔案對應關係
- **微服務 A (Core 核心業務)** ➔ 複製 `dist/core/Code.gs` 與 `dist/core/Bridge.html` 貼入【核心業務試算表】。
- **微服務 B (Chat 小組交流)** ➔ 複製 `dist/chat/Code.gs` 與 `dist/chat/Bridge.html` 貼入【小組交流試算表】。
- **微服務 C (Progression 成就履約)** ➔ 複製 `dist/progression/Code.gs` 與 `dist/progression/Bridge.html` 貼入【成就履約試算表】。

### 3.2 GAS 部署作業注意事項（防踩坑必讀）
1. **HTML 檔案型態**：在 GAS 編輯器中建立 `Bridge` 時，必須在左側點擊「**新增檔案 (+) ➔ HTML**」並命名為 `Bridge`（不可建為 `.gs` 指令碼檔，否則會報 `Could not find file: Bridge` 致命例外）。
2. **部署設定值 (Deployment Config)**：
   - 點擊「部署」 ➔ 「管理部署作業」 ➔ 點擊鉛筆「編輯」 ➔ 版本選「**新版本**」 ➔ 儲存。
   - **執行身分 (Execute as)**：必須為「**我 (Me - 擁有者)**」。
   - **誰可以存取 (Who has access)**：必須為「**所有人 (Anyone)**」。
   - ⚠️ **禁忌**：嚴禁點擊「新增部署作業」，否則會生成新的 Web App URL，導致線上 `runtime-settings.js` 失效。
3. **Progression 定時排程觸發器**：
   - 成就履約專案必須建立定時觸發器：函式選 `runDailyMilestoneSettlement`、時間來源選「時間驅動」、類型選「日計時器」、時段建議選「**凌晨 03:00 至 04:00**」（配合每日凌晨 03:00 打卡截止固化點）。
4. **歷史點數一次性遷移已完成且清理**：
   - 2026 年度歷史個人獎勵點數已全數自 `PlayerProgress` Col 2 遷移至 Col 5，一次性遷移函式（`runMigratePlayer2026Rewards()`）已在生產環境執行完畢並自 `dist/progression/Code.gs` 中徹底清理。常態夜間排程維持零遷移邏輯，部署時請勿再引入歷史遷移腳本。
5. **存活健康驗證**：部署完成後造訪 `https://<webAppUrl>/exec?format=json`，確認回傳 `{"status": "ONLINE"}`。

  * 正式站網址：`https://khya31.github.io/vitalapp/`（全召會聖徒正式使用）。

### 4.2 前端發布標準 SOP
> ⚠️ **工作目錄警告**：專案根目錄非 Git 倉庫，必須切換至 `src/frontend/` 執行 Git 指令！

1. 修改 `src/frontend/html/` 底下之程式碼。
2. **雙軌更新版本號（防快取咬死）**：
   - 遞增 `src/frontend/html/sw.js` 的快取版本號（**目前為 `vital-cache-v104`**）。
   - 同步更新 `index.html` 內引用之所有 CSS 與 JS 查詢字串（如 `?v=20261014-v104`）。
3. **提交與推送到測試專案**：
   ```bash
   cd src/frontend
   git status
   git add .
   git commit -m "feat/fix: 更新摘要說明"
   git push origin main
   ```
4. **測試站驗收**：開啟 `https://hsnu125739.github.io/vitalapp/`，確認新功能正常運作且 Service Worker 順利升級。
5. **正式站上線發布**：
   ```bash
   git push khya main
   cd ../..
   ```
6. **Token 憑證安全提醒**：GitHub PAT 已備份於專案最外層 `GIT_TOKEN.txt`，`src/frontend/.git/config` 內已脫敏清空明文，推送時請依本機 Git 憑證管理工具進行驗證。
