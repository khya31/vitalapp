# 💬 文檔六：聊天留言板架構書

> **目的**：闡述微服務 B (Chat) 的直欄矩陣、一則置頂、防刷互斥鎖、安全轉義與高效能通訊機制。

---

## 1. 系統定位與無鑑權極速設計

* **定位**：獨立於 Core 之外，專責小組交流高頻寫入與輪詢，防止佔用 Core 打卡頻寬與讀寫配額。
* **零鑑權假設**：封閉小組場景下信任用戶端，省去 Auth 開銷，換取 3ms~50ms 極速回應。
* **並發防護**：寫入時強制套用專屬 `LockService` 腳本鎖 `lock.waitLock(3000)` (3000ms 逾時熔斷機制) 與 `CacheService` (21600秒) 快取穿透防禦。
* **架構邊界與積分體系零耦合 (Zero Score-Side-Effects)**：
  * **微服務邊界標記**：線上生產環境聊天已全面由 Microservice B (`dist/chat/Code.gs`) 獨立承接；`src/backend/` 中保留之留言方法僅作為 `tests/` 單元測試之記憶體同構規格模擬。
  * **點數與履約系統隔離**：聊天留言板僅處理文字交流與置頂公告，完全獨立於 Progression 履約系統。本模組不包含、不參照亦不修改任何個人結算分 (`settledTotalScore`)、入組基準分 (`joinBaseScore`)、小組總分或小組歷程 (`historySummary`)。發言與公告操作保證零積分副作用。

---

## 2. 直欄矩陣拓撲 (Column-per-Group)

* **結構配置**：一組獨佔一縱向直欄 (Column)。寫入時互不干涉。
  * Row 1: `groupId` (組別 ID)
  * Row 2: 置頂公告 (JSON 字串：`{ content, authorName, authorPlayerId, postId, updatedAt }`，無公告為空字串)
  * Row 3: `totalPostsCount` (留言總數，模擬 HTTP 304 快速比對)
  * Row 4+: 留言記錄 (每列為一則 JSON 序列化字串)
* **$O(1)$ 直達定址**：前端帶入 `postsColIndex`，後端無須全表掃描直接讀寫該欄。
* **HTTP 304 快取模擬**：比對客戶端 `clientCount` 與 Row 3 總數，或比對 `sinceTimeMs` 增量，無新留言時立即返回 304 狀態 (耗時 3ms)，節省帶寬與時間。

## 3. 前端交互、安全防護與防連擊機制

* **本地樂觀追加新留言 (Optimistic Append - `TEMP_${Date.now()}`)**：
  * `ChatStore.sendMessage` 在發起網路請求的同一時刻，立即於本地佇列頂端插入帶有 `isPending: true` 與暫存 ID（`TEMP_${Date.now()}`）的樂觀留言氣泡，實現 0ms 零感知延遲發送。
  * 伺服器成功回傳權威確認物件後，平滑替換為正式 `messageId` 與真實時間戳，並更新 `postsColIndex` 持久化至快取；若遭遇錯誤則標記 `isFailed: true` 並提示重發。
* **發送表單互斥鎖與防連擊 (`isSubmittingMessage_`)**：
  * `GroupFellowshipView` 在表單 submit 時引入 `isSubmittingMessage_` 提交互斥鎖。
  * 送出當下立即將發送按鈕設為 `disabled` 並即時清空輸入框，防止使用者連擊 Enter 或連點發送按鈕造成重複發言與並發連線競爭。
  * 發送成功或拋出異常時，於 `finally` 區塊恢復按鈕可用狀態並讓輸入框重新獲得焦點。
* **Stored XSS 儲存型跨站腳本嚴格防護**：
  * 渲染組員留言氣泡時，除了訊息本文 `msg.content` 轉義外，抬頭作者名稱 `${this.escapeHtml(authorText)}` 亦強制進行 HTML 實體轉義編碼，徹底杜絕更名注入 XSS 威脅。
* **當前使用者姓名動態同步**：
  * `GroupFellowshipView` 採用動態 `currentUserName` Getter 與 Setter。
  * 當使用者更換暱稱成功後，`app.js` 即時指派更新，留言板發布新訊息立即採用新名稱，無須重新整理網頁。
* **前端智慧輪詢**：前端 `ChatStore` 以 45 秒為基礎進行自適應輪詢，並在視窗失焦時自動掛起以節省連線。
