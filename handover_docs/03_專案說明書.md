## 1. 專案基本資訊
- **名稱與版本**：高雄青職「活力同行」v2.0 (Canonical Architecture)
- **服務對象**：高雄市召會青年在職聖徒
- **願景**：生活即操練、同伴同行、生命長進
- **成長循環**：個人操練與個人成就 ➔ 同伴同行 ➔ 活力組全體累積（在籍貢獻分連動） ➔ 生命旅程篇章推進
- **點數守恆核心原則**：個人獎勵（里程碑、成就寶箱、個人同行激勵）全額計入個人當年度結算分 (`settledTotalScore`)，連動在籍貢獻分帶動小組總分，使小組總分完整反映全體成員的操練與個人卓越；並嚴格遵循「入組前不回溯、入組後同心累積、退組自動沉澱」之點數守恆律。

## 2. 角色權限體系
- **活力人 (Player)**：
  - 獨立回報每日四項操練（晨興、讀經、禱告、書報）與每週四項聚會（小排、禱告聚會、主日、相調探訪）。
  - 追求個人成就：解鎖讀經門檻里程碑、全勤成就寶箱與個人同行激勵獎勵，全額計入個人當年度結算分 (`settledTotalScore`)，並連動在籍貢獻分帶動小組總分。
  - 首頁點數感知：首頁右上角點數面板下半部（青綠卡片）即時呈現個人年度總點數；未入組時上半部小組點數固定顯示 "---" 且單位隱藏；點擊面板卡片即可打開「同行貢獻面板」檢視成果。
  - 查看個人生涯足跡、歷史統計與榮譽成果卡。
- **活力組同伴 (Group Member)**：
  - 自由輸入邀請碼加入活力組（上限 5 人）。
  - 晨興與探訪同行達標（$\ge 2$ 人）共享小組同行積分。
  - 小組總分同心累積：組員在籍期間的所有操練、聚會及個人獎勵，全額轉化為在籍貢獻分 ($\text{settledTotalScore} - \text{joinBaseScore}$)，匯聚成小組總分推進八大生命篇章；夜間排程同晚即時連動，同晚獲獎即時突破篇章門檻。
  - 首頁點數感知：首頁右上角面板上半部（桃紅卡片）即時呈現整組同心合意累積之篇章總點數；點擊上半部或下半部卡片均可開啟「同行貢獻面板」，清楚掌握組員同行在籍貢獻分與彼此扶持現況。
  - 小組交流看板互動，發布留言與同伴互勉。
- **活力組隊長 (Group Leader)**：
  - 建立小組並產生邀請碼。
  - 發布小組交流看板單則永久置頂公告。
  - 轉讓隊長職責（`transferGroupLeader`）。
  - ⚠️ **權限邊界澄清**：系統採聖徒自主自律加入與退出，隊長**無強制剔除組員 (Kick) 或審核申請之 API**；隊長若欲退組，必須先將隊長轉讓給其他組員；若為最後一人退組則小組自動解散 (`INACTIVE`)。
- **系統管理員 (Admin)**：
  - ⚠️ `admin.html` 已廢棄，維運由管理端 API 或由服事者直接於 Google 試算表後台處理。
  - 支援依分流規範發放個人同行激勵獎勵 (`targetType: 'PLAYER'`，直寫 Col 5) 或小組團體特殊獎勵 (`targetType: 'GROUP'`，寫入 Col 2)。

## 3. 核心功能與計分體系（v3.1 標準規範）

### 3.1 每日操練分值（滿分 140 點）
- **晨興 (50 點)**：**小組同行操練**。當日該組在籍成員須 $\ge 2$ 人打卡，才於排程結算時核發每人 +50 點小組同行分；個人單獨打卡晨興不發放小組分。
- **讀經 (30 點)**：**個人獨立操練**。聖徒未入組亦可獨立回報，全額計入個人生涯足跡。
- **禱告 (30 點)**：**個人獨立操練**。全額計入個人生涯足跡。
- **書報 (30 點)**：**個人獨立操練**。全額計入個人生涯足跡。

### 3.2 每週聚會分值（滿分 230 點）
- **小排聚會 (30 點)**：個人有參加即可回報，個人獨立計分。
- **召會事奉禱告聚會 (50 點)**：個人有參加即可回報，個人獨立計分。
- **主日聚會 (50 點)**：個人有參加即可回報，個人獨立計分。
- **外出看望相調探訪 (100 點)**：**小組同行操練**。當週該組在籍成員須 $\ge 2$ 人回報探訪，才核發每人 +100 點小組分。

### 3.3 成就、寶箱與獎勵記帳機制（2026 新記帳模型）
- **個人獎勵分流 (`targetType === 'PLAYER'`)**：
  - **涵蓋項目**：個人門檻里程碑（讀經門檻等）、連續操練/聚會成就寶箱（滑動視窗雙條件）、管理員發放之個人特殊同行獎勵。
  - **實體入帳**：累加直寫 `PlayerProgress` Col 5 (`settledTotalScore`)，消除寫入 Col 2 `historySummary` 的歷年年份鍵污染。
  - **在籍貢獻連動**：依公式 $\text{TenureContribution} = \max(0, \text{settledTotalScore} - \text{joinBaseScore})$，個人獲獎即時帶動個人對小組貢獻分與小組總分同步增長。小組總分真實反映組員個人操練與卓越成果，激勵同心合意！
- **小組獎勵分流 (`targetType === 'GROUP'`)**：
  - **涵蓋項目**：八大生命篇章晉級獎勵、小組人數達標獎勵、管理員發放之小組團體特殊獎勵。
  - **實體入帳**：累加寫入 `GroupProgress` Col 2 (`historySummary`)，作為小組歷程沉澱分。
  - **隔離防禦**：小組團體獎勵不灌水給個人結算分或個人在籍貢獻分，維持界限分明。
- **夜間排程同晚跨篇章即時連動**：
  - 在夜間排程批次結算 (`runBatchMilestoneSettlement`) 中，個人里程碑評估在先、小組篇章評估在後。
  - 組員達成個人成就獲獎時，即時原子同步更新個人記憶體結算分並累加至小組總分快照 (`groupScoreMap[pGid] += rewardPoints`)。
  - 緊接在後的小組篇章評估能即時感知包含組員個人獎勵的新總分，實現「組員同晚獲獎、小組同晚跨越門檻直接解鎖新篇章」。

### 3.4 首頁點數呈現架構與同行激勵互動（.hero-score-grid 改版規範）
為兼顧「個人忠信操練」與「活力小組同心同行」，首頁右上角點數面板（`.hero-score-grid`）確立雙卡分層架構：
- **上半部卡片：小組整組累積總點數 (`.hero-group-score`)**：
  - **未加入小組**：點數固定顯示 `"---"`，單位標籤（`<small id="homeGroupScoreUnit">`）自動隱藏。
  - **已加入小組**：呈現整組最新累積總點數（`groupTotalPoints`，包含小組歷史沉澱點數與全體在籍成員在籍貢獻分加總），並顯示「點」單位標籤。
- **下半部卡片：個人整年累積總點數 (`.hero-personal-score`)**：
  - 呈現聖徒個人整年度全額累積總點數（`personalPoints`，直連後端 Col 5 `settledTotalScore` 與歷史年度封存總和）。
  - 底層維持隱藏節點（`<span id="homeContributionText">`）同步更新個人在籍貢獻分（`contributionPoints`），確保歷史組件與自動化測試之向後相容性。
- **統一互動導航（同行貢獻面板）**：
  - 無論使用者點擊上半部小組卡片、下半部個人卡片，抑或外層 `.hero-score-grid` 容器，皆統一導航觸發開啟「同行貢獻面板」（`openContributionModal`），供聖徒快速查閱當年度在籍同行貢獻明細與同伴加成。
- **視覺色彩與設計規範**：
  - 採用既有色彩體系：上半部桃紅色（`#d66b91`）、下半部青綠色（`#2f8f7e`）。
  - 雙卡數值字級設定為 28px，搭配立體陰影與點擊手勢游標（`cursor: pointer`）。

## 4. 四大核心業務演算法與資料定理

1. **入組時間截斷定理 (Tenure Attribution)**：
   - 聖徒加入小組前之個人歷史操練與個人成就獎勵為個人資產，物理排除於小組總分與篇章之外（`recordDate >= joinedDate`）。
   - 加入小組時，系統自動將個人入組基準分錨定為當下個人總分（`joinBaseScore = settledTotalScore`），入組瞬間貢獻分嚴格為 0，杜絕帶分灌水。
   - 入組後所獲得之每日操練、每週聚會及個人成就獎勵，全額帶動個人在籍貢獻分與小組總分。
   - 生產端採用狀態快照差額計算，達到微秒級 $O(1)$ 算分：
     $$\text{TenureContribution}(m) = \max(0, \text{settledTotalScore}(m) - \text{joinBaseScore}(m))$$
   - 小組總分權威公式：
     $$\text{GroupTotalScore} = \text{GroupHistoryPoints}(\text{Col 2}) + \sum_{m \in \text{ActiveMembers}} \text{TenureContribution}(m)$$
2. **調組能量守恆定理 (Energy Conservation)**：
   - 嚴格維持「入組前不回溯、入組後同心累積、退組自動沉澱」之點數守恆律。
   - 組員退出小組時，其在籍期間累積之貢獻分（含個人操練、聚會與個人成就獎勵）全額沉澱至舊組 `GroupProgress.historySummary` 中（呼叫 `depositReward('GROUP', ...)`）；舊組總分完全守恆不減、解鎖篇章永不倒退。
   - 孤兒退組防禦：退組瞬間基準分必須重新錨定為當下個人總分（`newBaseScore = settledTotalScore`），防止未入組期間在籍貢獻分虛胖逃逸。
   - 轉入新組二次截斷：加入新組時，基準分重新錨定為當前最新個人總分，在新組之在籍貢獻分從 0 起算，絕不將舊組貢獻或入組前個人成果帶入新組。
3. **每週聚會每日增量差集結算 (Settled-and-Locked) 與金邊固化**：
   - 打破傳統每週一延遲結算。每日凌晨排程對當週已打卡聚會與 `_settledMeetings` 清單進行差集增量核發。
   - 結算完成之聚會項目即時鎖定並呈現發光金邊動效，防範跨夜惡意撤回。跨週時自動重置固化清單。
4. **夜間排程同晚跨篇章即時連動機制 (Same-Night Progression)**：
   - 深夜排程批次流水線中，組員個人里程碑評估在先、小組篇章評估在後。
   - 組員獲獎後即時原子累加小組總分記憶體快照（`groupScoreMap[pGid] += rewardPoints`），同晚直接突破篇章門檻解鎖新篇章並落盤 `TaskClaims` 憑證，消除隔日延遲體驗。

## 5. 技術棧與通訊拓撲總覽
- **後端**：Google Apps Script (V8 引擎) 三大微服務（Core, Chat, Progression）。
- **資料庫**：Google Sheets 物理三試算表（零基礎設施成本、天然視覺化審計軌跡）。
- **前端**：原生純淨 JavaScript (ES6+)、CSS3、PWA SPA，部署於 GitHub Pages。
- **通訊層**：Iframe RPC Bridge（以隱藏 Iframe + `postMessage` 雙向橋接穿透 GAS 302 跨域重定向）。
- **測試保護網**：`tests/` 21 測試套件、589 項自動化基準測試全數 PASS（含個人獎勵分流、Col 5 持久化、同晚跨篇章即時連動與點數守恆端到端回歸測試，以及首頁點數面板改版測試 `homeScorePanelRefactor.test.js`）。
