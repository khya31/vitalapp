## 3. 個人獎勵計入結算分與小組貢獻專項測試套件

為配合「個人獎勵由年份鍵改為累加至 `settledTotalScore` 並連動小組總分與貢獻」的重大重構，本系統建立了嚴密的專項測試防護網，涵蓋純領域、持久化、排程連動與端到端全生命週期：

### 3.1 `tests/unit/personalRewardGroupContribution.test.js`（全鏈路端到端回歸測試）
* **核心驗證定位**：全生命週期端到端閉環檢驗，徹底確認系統滿足「**入組前不回溯、入組後同心累積、退組自動沉澱**」點數守恆定律。
* **端到端六大核心情境**：
  1. **在籍成員達成個人里程碑／寶箱**：驗證組員達成個人門檻里程碑後，`settledTotalScore`（Col 5）、`personalPoints`、`contributionPoints`、`groupTotalPoints` 四者同步增加完全相同分值；`PlayerProgress` Col 5 實體寫入，Col 2 `historySummary` 保持純淨不含當年年份鍵，`TaskClaims` 產出個人憑證。
  2. **管理員發放個人特殊獎勵 (`grantTargetedReward` with `targetType: 'PLAYER'`)**：寫入 Col 5 並連動增加個人貢獻分與小組總分；Col 6 (`joinBaseScore`) 嚴格不受影響，寫入 `AdminLogs` 與 `TaskClaims`。
  3. **管理員發放小組特殊獎勵 (`grantTargetedReward` with `targetType: 'GROUP'`)**：維持寫入 `GroupProgress` Col 2 `historySummary`，增加小組總分；在籍組員個人貢獻分嚴格保持不變（小組獎勵不灌水給個人貢獻）。
  4. **入組前獲獎截斷防禦（未入組獲獎 ➜ 入組 ➜ 在組再獲獎）**：未入組聖徒個人操練獲獎，加入活力組時 `joinBaseScore` 自動錨定當時 `settledTotalScore`，入組瞬間貢獻分嚴格為 0，小組總分不被入組前點數灌水；在組期間再獲獎時，貢獻分精確轉為在組增量，物理排除入組前點數。
  5. **退組沉澱點數守恆與新組重新錨定（獲獎 ➜ 退組 ➜ 入新組）**：組員在組獲獎後退出活力組，包含個人獎勵在內的貢獻分全額沉澱至舊組 `historySummary`，舊組總分守恆不失分；退組後 `joinBaseScore` 重新錨定為當時結算分，隨後加入新組時貢獻分重新從 0 起算，新組不繼承舊組點數。
  6. **夜間排程同晚小組跨篇章連動端到端閉環 (`runBatchMilestoneSettlement`)**：真實落盤執行，組員同晚達成個人里程碑獲獎，推動小組總分即時突破門檻，小組在同晚直接解鎖新篇章，`PlayerProgress` Col 5、`GroupProgress` Col 3 與 `TaskClaims` 實體落盤。

### 3.2 `tests/unit/personalRewardSameNightSync.test.js`（夜間排程同晚小組篇章即時連動）
* **核心驗證定位**：驗證 `MilestoneCoordinator.runBatchMilestoneSettlement` 在夜間排程中個人獲獎與小組篇章之記憶體即時連動機制。
* **核心驗證情境**：
  1. **組員獲獎即時累加 `groupScoreMap`，同晚直接突破解鎖小組篇章**：當組員在夜間批次中達成個人里程碑獲獎時，即時同步更新 `pRowInfo.settledTotalScore` 並累加所屬小組 `groupScoreMap[pGid]`，使後續小組篇章評估能即時感知包含個人獎勵之最新總分，達到門檻時當晚直接解鎖新篇章，消除「隔日才解鎖」之體驗滯後。
  2. **多位同組成員同晚獲獎**：小組 `groupScoreMap` 原子累加全體獲獎組員之個人獎勵，加總計算無誤差。

### 3.3 `tests/unit/personalRewardLedgerPersistence.test.js`（進度帳本持久化層對齊 Col 5）
* **核心驗證定位**：進度帳本持久化層 (`ProgressLedger`) 對齊 Col 5 實體寫入與 Col 6 隔離專項測試。
* **核心驗證情境**：
  1. **`depositReward(PLAYER)`**：個人獲獎時寫入 `PlayerProgress` Col 5 (`settledTotalScore`)，Col 2 `historySummary` 不含當年年份鍵（消除歷史鍵污染），寫入寬度嚴格限定為 4（Col 2~5），Col 6 (`joinBaseScore`) 物理隔離不受影響。
  2. **`depositReward(GROUP)`**：小組獲獎維持寫入 `GroupProgress` Col 2 (`historySummary`)，寫入寬度為 3（Col 2~4）。
  3. **`batchApplyMilestoneSettlements`**：批次持久化個人里程碑時寫入 Col 2~5（寬度 4），同步更新記憶體快照 `pInfo.settledTotalScore`（Zero Drift），並具備 fallback 算分邏輯相容舊決策物件。
  4. **退組離隊沉澱守恆**：退組時呼叫 `depositReward(GROUP, ...)` 沉澱點數至舊組 Col 2，寫入寬度為 3，維持點數守恆。

### 3.4 `tests/unit/milestoneEngineDeep.test.js`（純領域里程碑引擎分流）
* **核心驗證定位**：純領域里程碑引擎深度測試與獎勵分流驗證。
* **核心驗證情境**：
  1. **個人獎勵分流 (`targetType === 'PLAYER'`)**：獎勵點數累加至出參 `updatedSettledTotalScore`（`baseSettledScore + totalRewardPoints`），`updatedHistorySummary` 維持原快照傳入值不變（不再將個人獎勵灌入年份鍵）。
  2. **小組獎勵分流 (`targetType === 'GROUP'`)**：維持呼叫 `depositToHistorySummary` 累加至小組 `updatedHistorySummary`，`updatedSettledTotalScore` 維持基準分。
  3. **邊界與數值防禦**：合法 0 點配置防 falsy 吞食、`settledTotalScore` 為 null/undefined/非數值時安全回退為 0 防 `NaN` 逃逸、`targetId` 空值 early return 決策物件補齊預設值。

## 5. 雙軌測試適配器架構 (Test Seam Bridge)

為支援重構過程中隨時驗證「舊規格契約」與「新實作代碼」的雙向一致性，設計統一適配層：

```
                    ┌───────────────────────────┐
                    │  tests/run-all.js Runner  │
                    └─────────────┬─────────────┘
                                  │
                    ┌─────────────▼─────────────┐
                    │ tests/engine/systemAdapter│
                    └──────┬─────────────┬──────┘
                           │             │
        (TEST_SYSTEM_TYPE) │             │ (預設)
                           ▼             ▼
       ┌──────────────────────┐ ┌──────────────────────┐
       │ tests/engine/        │ │ tests/engine/        │
       │ srcAdapter.js        │ │ referenceSystem.js   │
       │ (直連 src/backend/)  │ │ (行為規格基準參考)   │
       └──────────┬───────────┘ └──────────┬───────────┘
                  │                        │
                  └───────────┬────────────┘
                              ▼
               ┌──────────────────────────────┐
               │ tests/engine/mockDatabase.js │
               │ (記憶體 3 試算表 Mock 環境)  │
               └──────────────────────────────┘
```

1. **`systemAdapter.js`**：統一抽象工廠 `createSystem(type)`。可透過環境變數 `TEST_SYSTEM_TYPE=src` 動態將測試目標由基準引擎無縫切換為 `src/backend/` 新架構模組。
2. **`referenceSystem.js`**：基準行為規格參考引擎，模擬真實業務契約，作為防止代碼腐化的黃金保護網。
3. **`srcAdapter.js`**：模組接縫橋接器，將 `src/backend/` 下的純領域模組（`dailyMatrixModule`, `milestoneEngine`, `settlementEngine` 等）直通接入測試。
4. **`mockDatabase.js`**：純記憶體模擬 Core、Progression、Chat 三微服務試算表結構，零外部網路 I/O，百毫秒內完成數百次資料庫重置。

## 6. `node:vm` 沙盒化生產代碼契約校驗

為了確保 `dist/` 下生產產物（Google Apps Script 單檔）與 `src/` 一致，多個關鍵測試使用 Node.js 原生 `node:vm` 模組：

```javascript
const vm = require('node:vm');
const fs = require('node:fs');

// 建立模擬 GAS 全域環境
const sandbox = {
  Utilities: { formatDate: () => '...' },
  SpreadsheetApp: { ... },
  CacheService: { ... },
  LockService: { ... }
};
vm.createContext(sandbox);

// 直接執行 dist/ 產物以驗證線上邏輯
const code = fs.readFileSync('dist/core/Code.gs', 'utf-8');
vm.runInContext(code, sandbox);
```
此機制可嚴格斷言：
* GAS 專案語法正確性（防止因 Babel/Webpack 編譯導致 GAS V8 拋錯）。
* 實體函數命名與 Action 路由派發無誤。
* 固化與 IDOR 雙向校驗安全約束不可退化。

## 7. 新增測試標準與規範

1. **風格與框架**：
   * 強制使用 Node.js 原生語法 `const test = require('node:test'); const assert = require('node:assert');`。
   * 嚴禁引進 Jest、Mocha、Chai 等外部龐大測試依賴。
2. **斷言嚴格度**：
   * 數值斷言一律使用 `assert.strictEqual(actual, expected)`。
   * 物件/陣列斷言一律使用 `assert.deepStrictEqual(actual, expected)`。
3. **副作用隔離**：
   * 每個測試案例必須具有獨立性，嚴禁跨測試案例共用未重置之全域變數或快取狀態。
4. **驗收守則**：
   * 任何新功能開發或 Bug 修復，必須伴隨對應的單元測試或場景測試。
   * 交付前必須執行 `agy-node tests/run-all.js` 確保 589 項測試全數綠燈通過（21 suites，100% PASS，0 fail，0 skip，升級版號 v104）。
