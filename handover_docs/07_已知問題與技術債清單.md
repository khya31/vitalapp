## 3. 已修復之重大歷史 Bug 與技術債（防踩坑指南）

* **個人獎勵鎖定年份鍵未連動小組總分與在籍貢獻分 (P0，已於 2026-10 完成四階段重構徹底修復)**：
  * **歷史缺陷**：舊版純領域引擎 `MilestoneEngine.evaluate` 與總帳持久化層 `ProgressLedger.depositReward` 不論 `targetType` 是 `PLAYER` 還是 `GROUP`，只要獲發獎勵皆無差別呼叫 `depositToHistorySummary` 寫入 `PlayerProgress.historySummary["2026"]`（Col 2）。
  * **根本問題**：
    - 個人在籍貢獻分：$$\text{contributionPoints} = \max(0, \text{settledTotalScore} - \text{joinBaseScore})$$
    - 小組總分：$$\text{groupTotalPoints} = \text{sumHistoryPoints}(\text{Group Col 2}) + \sum_{m \in \text{ActiveMembers}} \text{contributionPoints}_m$$
    - 因個人獎勵寫入 Col 2 而未累加至 Col 5 (`settledTotalScore`)，導致組員在組期間獲得的所有個人成就、里程碑與個人同行特殊獎勵，無法帶動個人對小組的貢獻分增長，小組總分亦無法反映組員的個人卓越追求；且夜間排程迴圈中小組篇章總分快照滯後，導致當晚小組跨門檻篇章解鎖產生體驗延遲。
  * **重構解法與防踩坑規範**：
    1. **純領域分流**：`MilestoneEngine.evaluate` 進行領域分流，小組獎勵（`GROUP`）寫入小組 `historySummary`，個人獎勵（`PLAYER`）一律累加至出參 `updatedSettledTotalScore`，`historySummary` 保持純淨不再灌入年份鍵。
    2. **帳本持久化層對齊 Col 5**：`ProgressLedger.depositReward` 與 `batchApplyMilestoneSettlements` 實體寫入 `PlayerProgress` Col 2~5（欄寬 4），並同步更新記憶體快照 `pInfo.settledTotalScore`；嚴格物理隔離保護 Col 6 (`joinBaseScore`)，確保入組時間截斷算分不被破壞。
    3. **同晚小組篇章即時連動**：`MilestoneCoordinator.runBatchMilestoneSettlement` 在成員獲獎當下即時原子累加 `groupScoreMap[pGid]`，使小組同晚跨越門檻即時解鎖新篇章。
    4. **歷史遷移與零遺留代碼**：已執行一次性獨立遷移函式完成歷史 2026 點數對齊，過渡代碼全數清理完畢，零遺留技術債。
* **每週聚會結算週一強阻斷技術債 (P1，已改為每日凌晨單軌增量結算修復)**：
  * **歷史缺陷**：舊版每週聚會（小排、禱告聚會、主日聚會）僅在「週一凌晨強阻斷結算」，導致週間與週末聚會後點數延遲入帳，信徒在週末前無法看見操練進度回饋，且遇跨週調組時極易引發扣分衝突與時空錯位。
  * **重構解法與防踩坑規範**：
    1. **每日凌晨單軌增量結算**：徹底廢除週一強阻斷，全面改採「每日凌晨單軌增量差集結算（Settled-and-Locked）」，每日排程針對當週新打卡之聚會差集項目進行核算。
    2. **極簡狀態與集合差集**：於 `historySummary` 平鋪記錄 `_settledWeekKey` 與 `_settledMeetings: string[]`，跨週自動重置，同週僅比對增量差集。
    3. **結算即固化與尊榮金邊防禦**：已結算項目即刻標記為 `solidifiedItems` 回傳前端，卡片套用獨立 GPU 合成層發光金邊呼吸動效並鎖定撤回，徹底根除跨夜惡意撤銷與調組扣分骨牌效應。
* **打卡撤回「幽靈復活」缺陷 (Ghost Resurrection, P0)**：
  * 舊版在狀態合併時使用單調布林 OR 聯集（`cur || server || pending`），導致打卡反選取消（Uncheck）時被背景舊快照強制復活為 true。
  * **防踩坑規範**：嚴禁使用單調 OR 聯集！必須使用 `OptimisticPracticeStore` 之細粒度欄位突變追蹤（`dailyMutations`, `meetingMutations`），在途狀態 Latest-Wins，隊列清空後以伺服器權威為準；且已固化項目（`solidifiedItems`）永久為 true。
* **盲目信任客戶端行號越權漏洞 (IDOR, P0)**：
  * 舊版直接以前端傳入之 `matrixColIndex` 作為橫行號寫入 Players 表，攻擊者可偽造他人行號竄改小組與個資。
  * **防踩坑規範**：嚴禁盲信客戶端行號！所有端點必須經 `resolveAuthenticatedPlayerRow_` 雙向校驗首欄 `playerId`，不符強制 fallback 全表檢索。
* **試算表公式注入攻擊防禦 (Formula Injection, P0)**：
  * 使用者輸入若以 `=`, `+`, `-`, `@` 開頭，寫入 Google Sheets 會被試算表解析為公式執行。
  * **防踩坑規範**：所有寫入試算表之使用者輸入文字欄位（如姓名、暱稱、帳號、電話），在寫入前必須先設置單元格格式為純文字：`.setNumberFormat('@')`。
* **並發註冊與名冊擴充競態缺陷 (Race Condition, P0)**：
  * 多人同時掃碼註冊時，並行讀取相同 `lastRow`，導致名冊覆寫與直欄座標重疊。
  * **防踩坑規範**：涉及名冊列號分配與雙矩陣直欄擴展之端點，必須強制獲取 `LockService.getScriptLock().waitLock(10000)` 排他鎖。
* **入站參數容器遺失缺陷 (`normalizeInboundParams_`, P0)**：
  * 直接解構 `payload.data` 會在頂層扁平傳參時取到 `undefined`。
  * **防踩坑規範**：後端 Action 進入點必須統一調用 `normalizeInboundParams_(payload)` 正規化解包。
* **孤兒退組基準分歸零致貢獻暴增 (P0)**：
  * 舊版成員退組未入新組時將 `newBaseScore` 設為 0，導致該成員個人貢獻分（$\text{settledTotalScore} - 0$）瞬間暴增為歷史總分。
  * **防踩坑規範**：退組時基準分必須嚴格錨定為退組當下總分（`newBaseScore = settledTotalScore`），維持離隊期間貢獻分為 0。
* **長駐跨夜 `currentDate` 粘滯缺陷 (P1)**：
  * 舊版在 View 建構時以靜態字串賦值 `this.currentDate`，長駐過夜後打卡錯誤寫入昨日。
  * **防踩坑規範**：日期與週次必須使用動態 Getter/Setter，並透過 `visibilitychange` 監聽前景喚醒重新水合。
* **Streak 連勝里程碑餘數跳過漏洞 (P1)**：
  * 舊版使用 `streak % n === 0`，伺服器排程跳日恢復時 $streak = n + 1$，導致寶箱被永久漏發。
  * **防踩坑規範**：連勝里程碑判定必須使用【滑動視窗雙條件演算法】（$streak \ge n$ 且視窗內未曾領取）。
* **跨組幽靈調組漏洞 (P1)**：
  * 舊版在有組別狀態下可直接輸入新邀請碼加入新組，跳過原組組長防禦與解散邏輯。
  * **防踩坑規範**：非強制模式下已在組成員嚴禁直接加入新組，後端強制攔截並回傳 `ALREADY_IN_GROUP`。
* **小組交流板 Stored XSS 漏洞 (P1)**：
  * 舊版渲染組員留言氣泡時作者名稱未經轉義即直接拼入 innerHTML。
  * **防踩坑規範**：所有拼入 innerHTML 的動態文字（包括作者暱稱、訊息內容）必須強制使用 `escapeHtml` 轉義。
* **多日排程斷層結算中斷 (P1)**：
  * 舊版僅單日檢驗 `isNextDay`，漏跑 2 天以上結算中斷。
  * **防踩坑規範**：結算排程必須調用 `SettlementEngine.resolveCatchupDates` 生成時序遞增序列，循序補算推進；超長停機 (>7 天) 需由管理員分批手動推進。
* **首頁右上角點數面板文字重疊、結算中徽章擠壓與職責混淆 (P2，已於 v104 完成雙卡重構徹底修復)**：
  * **歷史缺陷**：

  * **重構解法與防踩坑規範**：
    1. **職責清晰之雙卡分流**：
       - **上半部（卡片 1）**：固定為【小組整組累積總點數】（`#homeGroupScoreText`）。尚未加入小組時顯示 `"---"` 且單位「點」自動隱藏；已在小組時顯示整組總點數與單位。

    2. **文字重疊與徽章絕對定位根治**：

    3. **統一互動開啟同行貢獻彈窗**：

## 4. 五大不可違背之架構不變量 (Invariants)

1. **Bounding-Box Batch Seam (最小包圍區間批次讀取)**：
   - 嚴禁在迴圈內串行呼叫 `SpreadsheetApp.getRange()` 或 `getValues()`。所有讀寫必須單次二維陣列批次處理。
2. **Defensive Parameter Sandbox (防禦性參數沙盒)**：
   - 成就規則解析必須有 `try-catch` 保護。規則語法錯誤時僅記錄 `AdminLogs` 並跳過，結算排程**絕對不允許中斷**。
3. **Cross-Midnight Date Invariants (跨午夜邊界保護、離線戳記與動態時鐘)**：
   - 嚴格以台灣時區 (GMT+08:00) 錨定日期天，前端全面採用動態 Getter/Setter 隔絕時區平移；**且前端離線打卡佇列 (`vital_offline_queue`) 必須強制攜帶 `targetDate` 戳記，跨越凌晨 00:05 結算點補送時，後端必須追溯評估昨日成就條件，保障資料最終一致性**。
4. **Fine-Grained Authoritative State Alignment (細粒度權威狀態對齊)**：
   - 前端狀態庫以細粒度欄位記錄在途突變，杜絕粗暴聯集覆蓋，保障撤回操作真實性。
5. **Conservation of Points & Tenure Isolation (點數守恆與入組時間截斷不變量)**：
   - 個人獎勵一律累加至 `settledTotalScore`（Col 5）；入組時 `joinBaseScore`（Col 6）嚴格錨定為當時個人總分；離隊時個人在籍貢獻分全額沉澱至舊組 `GroupProgress.historySummary`（Col 2）。任何情況下嚴禁將個人獎勵寫入個人 `historySummary` 年份鍵，嚴禁將離隊基準分歸零！

## 5. 前端互動與效能禁令

1. **嚴禁使用瀏覽器原生 `alert()` / `confirm()`**：
   - 原生彈窗會完全凍結 PWA 主執行緒與背景通信。全域一律改用 `VitalToast`（支援 `info`, `gold`, `success`, `error` 四色主題與三段位置）或自製 Modal。
2. **彈窗互動邊界（點擊遮罩關閉，禁 Escape 鍵）**：
   - 所有彈窗支援點擊外部遮罩（Click-Outside）關閉退出；但**嚴禁監聽或綁定鍵盤 Escape 鍵**，維持行動端純淨觸控邏輯。
3. **發光金邊動效禁止 CPU Repaint**：
   - 每週聚會卡片金邊呼吸動效**嚴禁對 `box-shadow` 做逐幀 CSS 動畫**；必須使用 `::after` 偽元素搭配 GPU 合成層原生加速之 `opacity: 0.25 -> 0.85` 循環，徹底杜絕發熱卡頓。
